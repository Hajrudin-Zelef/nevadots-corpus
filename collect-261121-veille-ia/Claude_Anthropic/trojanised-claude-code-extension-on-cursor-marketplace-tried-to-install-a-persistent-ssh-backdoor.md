# Trojanised Claude Code extension on Cursor marketplace tried to install a persistent SSH backdoor

**TLDR**

- Microsoft says the packages were never distributed from Visual Studio Marketplace or npm; evidence suggests only Cursor was affected.<sup>8</sup>
- Cursor says at most 5,000 users were affected, and attacker login was not possible on most macOS and Windows hosts.<sup>1</sup>
- Microsoft says the loader runs before the extension's code, and removing the extension does not remove the artifacts it wrote.<sup>8</sup>

Cursor said on 29 October that it had identified a security incident involving versions 2.1.312 and 2.1.313 of the Anthropic.claude-code extension in its VS Code extension marketplace, which it says Anthropic did not develop.<sup>1</sup> According to Cursor, a maliciously modified version was available from about 2:27am to 1:35pm PT that day and runs code that attempts to install a persistent SSH backdoor.<sup>1</sup> Cursor estimates that at most 5,000 users were affected, and The Hacker News and Dark Reading report that it will contact them directly.<sup>1</sup><sup>6</sup><sup>7</sup> WIRED reports that Phorion was the first to spot the extension, after detecting it on a customer's Mac.<sup>5</sup> Cursor says the code collects the hostname, username, operating system, architecture, home directory path, environment variable names, working directories, configured Git email and public IP address.<sup>1</sup> It also attempts to add an attacker-controlled SSH key to `authorized_keys`, switch on the local SSH service and open a reverse SSH tunnel, then tries to make that tunnel persistent through a LaunchAgent on macOS or a scheduled task on Windows, with background scripts retrying roughly every 60 seconds.<sup>1</sup> OpenSourceMalware's Jenn Gile told The Hacker News that the package identifies itself as `anthropic.claude-code` 2.1.313 but its main JavaScript bundle contains a 66-line loader inserted before the legitimate code.<sup>6</sup> Netskope reports that the loader sends host details to the attacker's server over HTTP on port 8099, and that the environment variable names it gathers are those matching `KEY|TOKEN|SECRET|PASS|AWS|GCP`.<sup>2</sup> The Hacker News says the collected data covers the names of up to 40 such variables and that no follow-on payloads have been observed.<sup>6</sup> Ars Technica reports that Phorion said the variable names would let an operator inventory cloud credentials and API tokens on a machine.<sup>3</sup>

Cursor says turning on the local SSH service requires admin rights, which the extension does not have on most macOS and Windows hosts, so the attacker could not have logged in through the tunnel there, although the extension still added the attacker's key, installed persistence and sent host details.<sup>1</sup> WIRED reports that a flaw in the malware's design stopped it fully establishing itself on the vast majority of targets.<sup>5</sup> Cursor says it removed the version, shut the marketplace down as a precaution, audited access, confirmed that no other extensions were tampered with, rotated its keys and rebuilt the marketplace, and that it worked with the hosting provider to take the attacker's server offline.<sup>1</sup> How the upload happened is not established. Ars Technica reports that independent researcher Kevin Beaumont and Phorion's CTO said 2.1.313 was distributed through Anthropic's official account on Cursor, and that neither Cursor nor Anthropic had explained how attackers gained control of it.<sup>3</sup> WIRED reports that Cursor did not answer whether the upload resulted from a breach at Cursor.<sup>5</sup> WIRED quotes Anthropic's Felix Rieseberg as writing on X that a malicious actor used access to Cursor's marketplace to publish a tampered copy, that the incident was not a compromise of Anthropic's systems or employee laptops, and that versions on Anthropic's official channels are not affected.<sup>5</sup> Dark Reading quotes Forever Security's Gal Weizman as saying that extensions are most often hijacked through theft of locally stored publishing credentials, and that two-factor authentication for publishing would mitigate the risk.<sup>7</sup>

The outlets differ on several details. On duration, Cursor's notice gives about 2:27am to 1:35pm PT on 29 October, Netskope says roughly 11 hours from about 09:27 to 20:35 UTC, and WIRED and Dark Reading also say about 11 hours.<sup>1</sup><sup>2</sup><sup>5</sup><sup>7</sup> The Ars Technica headline says "nearly 12 hours", while its body and The Verge give 5:27am to 4:35pm ET.<sup>3</sup><sup>4</sup> On versions, Cursor's notice, updated on 30 October to clarify affected versions, lists 2.1.312 and 2.1.313, while Netskope, Ars Technica and The Hacker News name only 2.1.313.<sup>1</sup><sup>2</sup><sup>3</sup><sup>6</sup> On platforms, Cursor's notice covers Windows and macOS, Netskope says the build targets `darwin-arm64` and `win32-x64` on Cursor and that the backdoor code also handles Linux, WIRED describes the extension as being for Windows, macOS and Linux, and Ars Technica says the code was written to work on all three.<sup>1</sup><sup>2</sup><sup>5</sup><sup>3</sup> On other channels, Netskope says the npm and VS Code Marketplace releases of 2.1.313 were pulled as a precaution and that OpenSourceMalware reports those and the Open VSX build were not malicious.<sup>2</sup> The Hacker News says there is no evidence the version reached Open VSX or Microsoft's marketplace, and notes that an earlier version of its story wrongly said Open VSX was compromised.<sup>6</sup> On Anthropic's response, Ars Technica reports that Anthropic had not issued a public notice to customers and did not answer its questions, while WIRED quotes two Anthropic staff members posting on X.<sup>3</sup><sup>5</sup> On the fixed release, Ars Technica cites Beaumont as saying Anthropic pushed 2.1.314 several hours after 2.1.313 appeared on Cursor, and The Hacker News says that, as of 30 October, 2.1.314 had been published to Open VSX and the Microsoft marketplace.<sup>3</sup><sup>6</sup>

Cursor tells anyone who installed or updated the extension in that period to check `~/.ssh/authorized_keys` for a key labelled `svc-telemetry`, use its remediation scripts, isolate affected hosts, remove the key, persistence and tunnel processes, and rotate credentials and sessions.<sup>1</sup> Both Cursor and Netskope say uninstalling the extension may not be enough, because the payload drops standalone persistence scripts.<sup>1</sup><sup>2</sup> Netskope lists the attacker server at 134.209.82[.]225, tunnel user `tunnel` on TCP port 22, and persistence files including `~/Library/LaunchAgents/com.apple.sysmond.plist` on macOS and a scheduled task named `SysMon` on Windows.<sup>2</sup>

**Why it matters:** removing or updating the extension does not clear the SSH keys, scripts and startup entries it wrote, Microsoft says, so affected hosts need those artifacts removed separately.<sup>8</sup>

**Update, 1 November 2026:** Microsoft Threat Intelligence has published its own analysis of the injected code in the tampered Claude Code extension, adding detail on how the loader works, where it persists, including on Linux, and how to clean up.<sup>8</sup> Microsoft says it confirmed that the malicious packages found on the Cursor marketplace were never published to or distributed from the Microsoft Visual Studio Marketplace or the npm package, and that all evidence suggests the incident is limited to the Cursor marketplace.<sup>8</sup> It says Anthropic confirmed to Microsoft that its systems were not compromised and that it did not develop the malicious package.<sup>8</sup> Microsoft lists the affected versions as 2.1.313 and 2.1.312, matching Cursor, and attributes the live period of about 2:27am to 1:35pm PDT to Cursor while describing the extension as served for a few hours.<sup>8</sup><sup>1</sup> Netskope says the npm and VS Code Marketplace releases of 2.1.313 were pulled as a precaution, while Microsoft says the malicious packages were never published to or distributed from those channels.<sup>2</sup><sup>8</sup>

Microsoft says the injected function ran before the extension's expected code and used Node.js APIs, embedded components and built-in system tools to set up persistent access without downloading another executable.<sup>8</sup> It says the loader suppresses command output and silently catches errors, while the extension keeps working normally.<sup>8</sup> The callback sends the names of matching environment variables, not their values, which Microsoft says reveals potentially sensitive configuration categories but does not demonstrate theft of the secrets stored in them.<sup>8</sup> On keys, Microsoft says the loader appends an embedded Ed25519 public key to `authorized_keys` if no entry labelled `svc-telemetry` is present, and decodes a separate private key for the outbound connection, written first to a hidden temporary file named `.stk_` followed by ten hexadecimal characters derived from the hostname and home directory, and used to connect as the remote account `tunnel`.<sup>8</sup> The tunnel is launched with `-N -R '*:0:localhost:22'`, which asks the attacker's server to allocate a remote port and forwards connections to port 22 on the victim's loopback interface, with host-key checking disabled.<sup>8</sup> On Unix-like systems it prefers autossh and falls back to ssh, while on Windows it uses a hidden PowerShell loop, and each loop waits sixty seconds before retrying.<sup>8</sup> Microsoft says a running SSH process does not necessarily mean the attacker gained access, and repeats Cursor's account that errors and administrator-permission requirements blocked SSH access on most macOS and Windows hosts, while the malware could still plant its key, establish persistence and report host details.<sup>8</sup>

On persistence, Microsoft lists a macOS user LaunchAgent with RunAtLoad and KeepAlive at `~/Library/LaunchAgents/com.apple.sysmond.plist`, plus `~/.config/.smt` and `~/.config/.smtk`.<sup>8</sup> It also lists a Linux user-crontab `@reboot` entry using the same two files, which goes beyond Cursor's notice covering Windows and macOS.<sup>8</sup><sup>1</sup> On Windows it lists an attempted `SysMon` scheduled task requesting SYSTEM execution, with `smt.cmd` and `smtk` under `%USERPROFILE%\.config`, and a fallback `sysmon.cmd` in the user's Startup folder.<sup>8</sup> Microsoft says the presence of an artifact alone does not establish that the startup mechanism ran successfully.<sup>8</sup>

For response, Microsoft advises preserving the extension package, modified SSH authorisation files, generated keys, scripts and startup configuration before cleanup, and isolating devices with evidence of loader execution or backdoor installation.<sup>8</sup> On Windows it says to check both `%USERPROFILE%\.ssh\authorized_keys` and `C:\ProgramData\ssh\administrators_authorized_keys`, to confirm a key against the fingerprint in its indicators of compromise before removing the exact entry, and not to treat a missing marker alone as a substitute for reviewing installation, process, network and persistence evidence.<sup>8</sup> It says startup objects named like monitoring components must have their configured actions inspected before removal, and that credentials or sessions should be rotated or revoked when investigation indicates exposure.<sup>8</sup> Microsoft says removing or updating the extension does not remove artifacts written outside its installation directory, and that Cursor's reported takedown of the attacker's server does not remove artifacts already on a device.<sup>8</sup> It also says Microsoft customers can use the detections and hunting guidance in its post once the listed coverage and query validation gates are complete.<sup>8</sup>
