# Xcode 27.3 Beta is Out--Build 27C5020n Puts GitHub Copilot in the Coding Assistant Beside Claude, ChatGPT and Gemini, Carries the SDKs for Touch on Mac Three Days Before Apple's November 6 Date for the Touch-Screen MacBook Pro, and Needs macOS Tahoe 26.6 or Later

Xcode 27.3 beta 1 is out for developers. Apple's developer releases page lists it as build 27C5020n, dated November 3, five days after Xcode 27.2 shipped on October 29. Apple's release notes put one line under Coding Intelligence, "GitHub Copilot is now available in the coding assistant," and the beta carries the SDKs for macOS 27.3 and for Touch on Mac, three days before Apple's November 6 date for the touch-screen MacBook Pro. It requires macOS Tahoe 26.6 or later.

## GitHub Copilot joins Claude, ChatGPT and Gemini in the assistant

GitHub's changelog entry of November 4 calls the integration a public preview that starts with the Xcode 27.3 beta, set up from Xcode's Settings under Intelligence, with "All Copilot plans are supported" and the separate GitHub Copilot for Xcode extension left in place as "a separate option." By our count it is the fourth company's coding agent inside Apple's editor. 9to5Mac's report traces the sequence: ChatGPT arrived with Xcode 26, then Anthropic's Claude, Xcode 26.3 made both agentic with OpenAI's Codex and Claude Agent, and Xcode 27 added Google's Gemini. Apple's June 8 press release on Xcode 27 named "Anthropic, Google, and OpenAI" as the agent makers and said GitHub and Figma were the first to offer "seamless installation" of their tools as Xcode plug-ins; five months on, Copilot is in the assistant itself rather than beside it. 9to5Mac's point is the practical one: a developer whose company standardized on Copilot can now use it inside Xcode.

## The SDKs for a Mac you touch

The notes mention touch once, as a known issue: when Device Hub drives a device "via Sidecar or a Mac with Touch, only two touches can be sent to the target device," because three or more are read by macOS as a system gesture, and the workaround is to turn off touch gestures in Settings under Touch Display. The touch work itself is on Apple's Touch on Mac page, which lists Xcode 27.3 beta under Tools and documentation as the way to "build, run, and test your app," three Tech Talks, and Group Labs with Apple engineers on November 18 and 19. Apple's October 28 press release for the MacBook Pro with PROLED XDR Display says "many existing apps work with Touch right away, because macOS automatically translates touches into clicks," and that "updated system gesture APIs" let developers design for touch on purpose. Apple's Tech Talk "Bring Touch to your Mac app" is the how: move from "classic mouse tracking APIs to modern gesture recognizers and touch-native controls," enlarge hit targets, handle multi-touch, and manage system gestures, with a chapter on disabling them. Apple says the machine begins arriving Friday, November 6; our October 29 report has the prices.

## Siri AI testing runs through Xcode, but not through these notes

MacRumors' report counts "the ability for developers to test Siri AI integration in their apps" as the beta's second feature. The release notes have no Siri entry. What Apple's Siri AI Developer Preview documentation says is that you test by building your app with Xcode, signing it with a development profile and running it on a device that supports the preview, or through internal TestFlight testers, and that "the Siri Integration Advisor in Xcode provides feedback and suggestions" on an App Intents implementation. Our November 4 report on macOS 27.3 beta 1 has the preview itself.

## The rest of the notes

Xcode 27.3 beta includes Swift 6.4 and the SDKs for iOS, iPadOS, tvOS, watchOS, macOS and visionOS 27.3, debugs on device back to iOS 17, and requires macOS Tahoe 26.6 or later, so a Mac on Tahoe builds for Golden Gate without running it. Device Hub installs a dropped .app or .ipa and opens a dropped link on the device; UI tests can now be written with Swift Testing and XCUIAutomation; a new XCUIHinge class sets the hinge angle of an iPhone Duo in automation; plus nine Previews fixes and a Simulator fix. 9to5Mac expects the release in December, with macOS 27.3.

## Then and now

On November 5, 2003, our item on Xcode Update 1.0.1 reported the first update to Xcode 1.0, for an IDE bug "that could potentially lead to data corruption or the loss of files particularly when source files contain illegal characters," and said we had installed it "with no apparent ill effects." Our December 22, 2003 item on Xcode 1.1 had the next one arrive through Software Update, and our November 1, 2006 item on Xcode 2.4.1 carried a security fix for GDB. Twenty-three years on, a point release's headline is whose agent writes the code. We'd still read the notes before we let any of them near a project.
