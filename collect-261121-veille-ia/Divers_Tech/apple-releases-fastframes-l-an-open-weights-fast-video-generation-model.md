# Apple releases FastFrames-L, an open-weights fast video generation model

Unicorn News Desk ·

## Key facts

- Models
- FastFrames-L (14B) and FastFrames-S (1.3B)
- Output
- 832 × 480 video, 81 frames at 16 fps
- Sampling steps
- Two-step autoregressive video diffusion
- Base model (L)
- Distilled from Wan2.1-14B
- Measured latency (S, 1 GPU)
- 35.4 ms total for listed components (paper: 36 ms)

Apple has published FastFrames-L, a 14-billion-parameter open-weights text-to-video model, on Hugging Face, alongside a smaller 1.3-billion-parameter sibling called FastFrames-S. Apple describes both as autoregressive, two-step video diffusion models that generate 480p video at what it calls “interactive latency”.

The release accompanies a research paper titled “FastFrames: Video Generation at Interactive Latency,” and the repository is presented as the official implementation of that work. Early reaction on X has framed it as a world model. The account @techfren called it “a very impressive open weights world model”.

## What Apple released with FastFrames

The Hugging Face repository contains more than one model. According to the model page, Apple releases:

- **FastFrames-S** , a 1.3B-parameter model.
- **FastFrames-L** , a 14B-parameter model.
- An **optimised version of LingBot 1.3B** , which Apple says is 16x faster than the official model and “allows fluid camera-conditioned control”.

For FastFrames-L, Apple also publishes the intermediate checkpoints from its training pipeline: a causal teacher trained on latents generated by Wan2.1-14B, a consistency-distilled model, a DMD-distilled model, and the final generator with its pixel decoder and KV refinement network. Teams that want to study or rework the distillation steps can start from any of these stages, not only from the finished model.

The paper lists seven authors: Gene Chou, Guandao Yang, Fujun Luan, Lars Mescheder, Wei Dong, Stephan R. Richter and Vladlen Koltun. It is cited as arXiv preprint 2611.23226.

## How FastFrames works, in Apple’s description

Two terms matter here. An *autoregressive* video model produces a clip piece by piece, with each new part conditioned on what came before, rather than producing the whole clip in one pass. A *diffusion* model creates an image or video by starting from noise and removing it over a series of steps. Many diffusion models use dozens of steps. Apple says FastFrames uses two.

The two models start from different places. For FastFrames-S, Apple keeps a two-step, frame-wise Causal Forcing++ generator frozen and trains the networks around it. For FastFrames-L, Apple first distils Wan2.1-14B into a two-step causal model following the Causal Forcing++ recipe, then trains its pixel decoder and KV refinement network the same way as for FastFrames-S. *Distillation* means training a faster model to imitate a slower, larger one. A *KV cache* stores the attention “keys” and “values” computed for earlier frames so the model does not recompute them for every new frame.

Apple’s latency profile shows where the time goes. For FastFrames-S on one GPU at 480p with a full KV cache, the page lists four components, each called once:

- DiT evaluation at t=1000: 16.1 ms
- DiT evaluation at t=833: 16.2 ms
- KV refinement: 2.2 ms
- Pixel decoder: 0.9 ms

Those add up to 35.4 ms, against 36 ms reported in the paper. The two DiT (diffusion transformer) evaluations correspond to the two denoising steps, and together they account for most of the time. The page does not publish a comparable per-component breakdown for FastFrames-L. Its profiling command for the larger model runs across 8 GPUs.

## How FastFrames-L relates to other open video models

The closest reference point is the model FastFrames-L is built on. Hugging Face’s model tree lists Wan-AI/Wan2.1-T2V-14B as the base model for apple/FastFrames-L. In practice, FastFrames-L is a faster, distilled descendant of that open model rather than a model trained from scratch. Apple thanks the authors of Wan2.1, Self-Forcing and Causal Forcing++ for releasing the code on which FastFrames builds.

The second comparison Apple makes is with LingBot. Apple says its optimised LingBot 1.3B is 16x faster than the official model. The repository includes an interactive demo built on it that can run on one GPU or on eight, served in the browser on a local port.

On output quality, Apple points to VBench, a benchmark suite for video generation. The repository includes an evaluation guide to reproduce the Quality, Semantic and Total scores from Table 1 of the paper. The model page does not reproduce those scores, so this article does not report them, and no third-party leaderboard results for FastFrames are available among the sources reviewed. Any quality ranking against other open video models currently rests on Apple’s own paper.

The “world model” framing also needs care. Apple’s page describes FastFrames as video generation at interactive latency. The world-model label comes from outside commentary, although the camera-controlled LingBot demo, where a user steers the viewpoint as video is produced, is the kind of use that label usually refers to.

## Access, hardware and the licence

The weights and code are on Hugging Face under the apple/FastFrames-L repository. Setup uses the `uv` Python tool from the repository root, and the FastFrames and third-party weights are downloaded by following a checkpoint guide. A basic text-to-video run takes a prompt and a seed. Apple’s example prompt is “A corgi surfing a wave at sunset”, and the output is an 832 × 480 MP4 of 81 frames at 16 fps. Switching from the small to the large model only requires changing the model flag to `ff-l`. A separate script regenerates the 20-plus videos shown on the project page for either model.

The listed hardware requirement is Linux on x86-64 with an NVIDIA GPU and a CUDA 12.8-compatible driver. The model page does not mention running FastFrames on Apple silicon. That differs from an earlier Apple research release built for speed: FastVLM, Apple’s fast vision-language model, came with checkpoints for MLX and CoreML on Hugging Face, plus an iOS/macOS demo app based on MLX.

Licensing is split. According to the model page:

- LingBot-World v2 code and weights follow their upstream CC BY-NC-SA 4.0 licence.
- All other FastFrames code is licensed under the Apple Sample Code License.
- Third-party code is listed in a separate ACKNOWLEDGEMENTS file.

The page names the licence for the FastFrames code but does not separately state terms for the FastFrames weights. Builders should read the licence files in the repository before using the models in a product, and should treat the LingBot-based components under their own Creative Commons terms.

## What FastFrames means for builders

Open weights matter here because they let teams adapt a model on their own infrastructure. Fastino, a company that builds on open-weight models, argues that an open base lets “teams without frontier-scale compute” post-train models for their own tasks, and that a released checkpoint “can become a family of models, post-trained, distilled, quantized, or otherwise adapted by anyone who chooses to build on it”. FastFrames is an example of that pattern: Apple took an open model, Wan2.1-14B, distilled it, and released the result along with every intermediate checkpoint.

For developers working on video, the practical points are:

- **Low latency, by Apple’s measurement.** The 35.4 ms component total for FastFrames-S on one GPU is Apple’s own figure, measured under its stated conditions. It is the most concrete number in the release and the one to check first on your own hardware.
- **Short, low-resolution clips.** The default output is 832 × 480 at 16 fps and 81 frames. This targets fast feedback and interactive use, not finished high-resolution footage.
- **Larger model, more hardware.** Apple’s profiling example for FastFrames-L uses 8 GPUs. Single-GPU speed for the 14B model is not stated on the page.
- **A full training trail.** Releasing the teacher, consistency-distilled and DMD-distilled checkpoints gives researchers material to study how much quality each step costs or saves.

The release also fits a line of Apple research focused on latency. Apple presented FastVLM as a way to meet “the low-latency demands of real-time applications”. FastFrames applies a similar focus to video generation, though this time on NVIDIA hardware.

## Open questions and what to watch next

Several points are not settled by the available sources:

- **Independent quality results.** VBench scores sit in the paper’s Table 1, and Apple provides a script to reproduce them. Third-party reproductions, and placement on public video leaderboards, will show how FastFrames-L’s quality compares with its Wan2.1 base and with other open video models.
- **Real-world latency for FastFrames-L.** The detailed per-component timing on the page covers FastFrames-S on one GPU. Measurements of the 14B model on common hardware setups will matter more to most teams.
- **Licence details for the weights.** The split between the Apple Sample Code License and CC BY-NC-SA 4.0 means commercial users will need a careful read of the repository files.
- **Apple silicon support.** FastFrames ships for Linux and NVIDIA only. An MLX or CoreML port, as happened with FastVLM, would broaden who can run it.
- **Community builds.** Its base model already sits in an active ecosystem on Hugging Face. Fine-tunes, quantised versions and integrations of FastFrames-L are the next signal of whether developers adopt it.

## Frequently asked questions

### Is FastFrames open source?

Apple released the model weights and code on Hugging Face. The FastFrames code is under the Apple Sample Code License, while the LingBot-World v2 code and weights it includes follow their upstream CC BY-NC-SA 4.0 licence. The page names the code licence but does not separately spell out terms for the FastFrames weights, so builders should read the licence files before shipping.

### How does FastFrames-L compare with Wan2.1?

FastFrames-L is derived from Wan2.1-14B. Apple distilled it into a two-step causal model and added a pixel decoder and a KV refinement network. The model page points to VBench quality, semantic and total scores in the paper's Table 1 but does not list the numbers itself.

### How fast is FastFrames?

Apple's example profile for the smaller FastFrames-S on one GPU at 480p, with a full KV cache, adds up to 35.4 ms across the listed components, against 36 ms reported in the paper. The page does not give an equivalent breakdown for FastFrames-L, whose profiling command uses 8 GPUs.

### Can FastFrames run on a Mac?

The installation instructions list Linux x86-64 with an NVIDIA GPU and a CUDA 12.8-compatible driver. The model page does not mention Apple silicon or MLX support.

### Is FastFrames a world model?

Apple's page describes FastFrames as video generation at interactive latency, and it ships a camera-controlled demo built on LingBot. Some observers, such as the X account @techfren, have called it an open-weights world model.
