### macOS MDM Configuration

Distribute via MDM using the `com.openai.codex` preference domain.<sup>21</sup> Codex honors standard macOS MDM payloads (Jamf Pro, Fleet, Kandji, etc.). Encode TOML as base64 without line wrapping:

| Key | Purpose | 
|---|---|
| `config_toml_base64` | Base64-encoded managed defaults (starting values users can change) | 
| `requirements_toml_base64` | Base64-encoded admin-enforced requirements (users cannot override) | 

**Precedence** (highest to lowest):

1. macOS managed preferences (MDM), `com.openai.codex:requirements_toml_base64`
2. Legacy `managed_config.toml` fields that the client reinterprets as requirements
3. Cloud-managed requirements delivered in the cloud config bundle (ChatGPT Business / Enterprise)
4. The system file: `/etc/codex/requirements.toml` on macOS and Linux,`%ProgramData%\OpenAI\Codex\requirements.toml` on Windows

Higher-precedence layers override scalar and list values from lower layers, and tables merge by key; rules, hooks, and filesystem restrictions have their own composition behavior. The cloud layer is not best-effort. The client uses a valid, identity-matched cached bundle when it has one, and if the fetch fails or times out with no valid cache, loading the cloud bundle returns an error instead of starting without the cloud-managed requirements.<sup>219</sup>

### OpenTelemetry Integration

Telemetry export is off by default. Opt in under `[otel]` in `config.toml`; the standard `OTEL_EXPORTER_OTLP_*` environment variables do not turn it on:<sup>220</sup>

```
[otel]
environment = "production"       # Tag on emitted events (default "dev")
log_user_prompt = false          # Raw user prompts stay out of the logs unless you opt in
exporter = { otlp-http = { endpoint = "https://otel-collector.internal:4318/v1/logs", protocol = "binary" } }          # Log events
trace_exporter = { otlp-http = { endpoint = "https://otel-collector.internal:4318/v1/traces", protocol = "binary" } }  # Trace spans
span_attributes = { team = "platform", cost_center = "eng-42" }   # Added to every exported trace span
```
- The exporter endpoint, protocol, and headers come from `[otel]` .`exporter` sends log events, and`trace_exporter` and`metrics_exporter` are separate keys; each takes`otlp-http` (with`endpoint` and`protocol` ) or`otlp-grpc` (with`endpoint` ), plus optional`headers` . With no exporter set, Codex records events but sends nothing
- Codex continues an incoming trace when the `TRACEPARENT` environment variable is set (with optional`TRACESTATE` ), and propagates trace context to its API calls, enabling end-to-end observability
- **Trace metadata (v0.130.0+).** v0.130.0 made trace metadata configurable.<sup>91</sup> At v0.167.1 the key is`span_attributes` , a table of string attributes added to every exported trace span, for dimensions such as team, cost center, or project ID
- Administrators can enforce the exporters and the individual logging settings in `requirements.toml`
- Keep privacy requirements in mind before enabling prompt or response logging: `log_user_prompt` and`log_agent_responses` export text that may contain code

### Enterprise Access

- **ChatGPT Business / Enterprise / Edu** : Org-admin controlled access, with cloud-fetched requirements applied automatically. Supports SSO via SAML/OIDC through your identity provider (Okta, Entra ID, etc.)
- **API** : Standard API auth, billing, and org/project controls. OpenAI publishes SOC 2 Type II and SOC 3 reports; HIPAA BAA available for Enterprise tier
- **Codex SDK** : Embed in internal tools and workflows
- **Policy enforcement at scale** : Use MDM-distributed`requirements_toml_base64` or filesystem-level`/etc/codex/requirements.toml`

**Data handling and compliance:**

- API inputs/outputs are not used for training under OpenAI’s Business/Enterprise/API terms
- For data residency, OpenAI API traffic routes through US-based infrastructure by default; for EU data residency requirements, consult OpenAI’s Enterprise sales team
- Session transcripts are stored locally; only API calls leave the machine
- ChatGPT Enterprise supports compliance frameworks including SOC 2, GDPR, and CCPA

### Rollout Strategy

Recommended phased rollout for organizations:

1. **Pilot** : Deploy to 3-5 senior engineers with`requirements.toml` enforcing the`read-only` sandbox with`on-request` approvals and`cached` web search. Collect feedback on AGENTS.md patterns and MCP server needs.
2. **Team expansion** : Roll out to full team. Distribute team-standard`config.toml` via MDM or repo. Enable`workspace-write` sandbox for trusted repositories.
3. **CI integration** : Add`codex-action` to CI/CD pipelines for automated PR review and test generation. Pass`--ephemeral` to`codex exec` when a run should leave no session files on the runner; it does not affect cost.<sup>246</sup>
4. **Org-wide** : Deploy via MDM with`requirements.toml` enforcing approved MCP servers, sandbox policies or permission profiles, and the model provider. It can set new-thread model defaults but has no model allowlist.

### Audit Patterns

Track Codex usage and enforce compliance:

- **OpenTelemetry traces** : Monitor API call volume, token usage, and latency per team
- **Session persistence** : Audit`~/.codex/sessions/` for compliance review (`codex exec --ephemeral` runs without writing session files; the interactive TUI has no such flag)<sup>246</sup>
- **MCP identity enforcement** : a server that`requirements.toml` does not approve is disabled, and`codex mcp list` reports the reason as`requirements (<source>)` , which shows what policy turned off on a given machine
- **Git audit trail** : All Codex file changes go through standard git — review via branch history and PR diffs

## Best Practices & Anti-Patterns

### Prompting Patterns

1. **Constraint-driven prompts** : Lead with boundaries. “Do NOT change the API contracts. Only refactor internal implementation.”
2. **Structured reproduction steps** : Numbered steps produce better bug fixes than vague descriptions
3. **Verification requests** : End with “Run lint + the smallest relevant test suite. Report commands and results.”
4. **File references** : Use`@filename` to attach specific files to context
5. **Outcome-driven loops** : “Implement, run tests, fix failures, stop only when all tests pass.” Codex iterates until done

### Testing Philosophy

The community converges on test-driven AI collaboration:<sup>22</sup>

- Define tests upfront as completion signals
- Let Codex iterate until tests pass (red → green → refactor)
- Consider Tiger Style programming patterns, which one contributor to that thread reports trying with Codex
- Provide exact file text when requesting patches. Codex uses strict matching, not fuzzy AST-based patching

### Context Management Best Practices

- Provide high-quality local documentation rather than relying on web search
- Maintain structured markdown with tables of contents and progress files (“progressive disclosure”)
- Normalize line endings (LF vs CRLF) across tracked files to prevent patch failures
- Keep `AGENTS.md` concise, since long instructions get pushed out of context

### Git Workflow

- Always create a new branch before running Codex on unfamiliar repos
- Use patch-based workflows (`git diff` /`git apply` ) rather than direct edits
- Review Codex suggestions like code review PRs
- Use `/diff` to verify changes before committing

### Community Skills

The feiskyer/codex-settings repository is a community-maintained set of skills, profile files, and command rules. It installs as a plugin marketplace:<sup>23</sup>

```
codex plugin marketplace add feiskyer/codex-settings
codex plugin add codex-settings@codex-settings
```
**Skills it ships** (a selection):

- `claude-skill` : Delegate a task to the Claude Code CLI, typically a headless`claude -p` run
- `deep-research` : Multi-source research split into sub-tasks, invoked explicitly with`$deep-research`
- `github-fix-issue` : Investigate or fix a GitHub issue by number or URL
- `github-review-pr` : Review a pull request by number or URL for evidence-backed defects
- `code-simplifier` : Simplify existing code without changing behavior

The repository also carries profile files for ChatGPT, Azure, GitHub Copilot, and OpenRouter (`<name>.config.toml`). It no longer ships reusable prompts: custom prompts in `~/.codex/prompts/` were removed from the CLI in v0.118.0 (PR #16115), and skills replace them.<sup>240</sup>

### Anti-Patterns

Common mistakes that waste tokens, produce poor results, or create frustrating workflows.

### Cost Anti-Patterns

| Anti-Pattern | Why It Fails | Fix | 
|---|---|---|
| Using `xhigh` reasoning for everything | Higher token cost with diminishing returns on simple tasks | Use `medium` by default; reserve`xhigh` for multi-file architecture decisions | 
| Never using `/compact` | Context fills to 272K, responses degrade | Compact after every major milestone or when `/status` shows >60% usage | 
| Running flagship model in CI | Expensive for routine checks | Create a `ci` profile with`gpt-6-luna` and`low` reasoning | 

### Context Anti-Patterns

| Anti-Pattern | Why It Fails | Fix | 
|---|---|---|
| Open-ended “explore everything” prompts | Codex reads dozens of files, burning context on irrelevant code | Scope with specific files: “Review `src/auth/login.py` and`tests/test_auth.py` “ | 
| No `AGENTS.md` in the project | Codex wastes turns discovering project structure | Add a 20-line `AGENTS.md` with key paths, conventions, and test commands | 
| Attaching entire directories | Floods context with irrelevant files | Use `@filename` to attach only the files Codex needs | 

### Workflow Anti-Patterns

| Anti-Pattern | Why It Fails | Fix | 
|---|---|---|
| Working on `main` directly | No safety net; risky edits are hard to revert | Always create a feature branch before starting Codex | 
| Skipping `/diff` before committing | Codex may have made unintended changes | Review `/diff` after every task, before any commit | 
| Ignoring test output | Codex iterates past failures if you don’t flag them | Use “run tests and stop only when all pass” in your prompt | 
| Never forking conversations | One wrong turn pollutes the entire context | `/fork` before risky explorations; discard bad branches | 

### Prompt Anti-Patterns

| Anti-Pattern | Why It Fails | Fix | 
|---|---|---|
| “Fix the bug” (no context) | Codex guesses which bug, reads everything | “Fix the TypeError in `src/api/handler.py:42` —`user.name` is None when unauthenticated” | 
| Multi-task prompts in one message | Codex conflates tasks, misses some | One task per message; use steer mode (Tab) to queue follow-ups | 
| Repeating context every message | Wastes tokens on duplicate information | Put standing facts in AGENTS.md (or turn on memories with `memories = true` ); reference earlier context |

| `claude --resume` | `codex resume` |

**Key differences to understand:**

- **Start with `/import`** : it selectively imports setup, project configuration, and recent chats from Claude Code (v0.140.0+), and since v0.145.0 migrates Cursor settings, MCP servers, plugins, sessions, commands, and project-scoped memories too.<sup>107</sup><sup>117</sup>
- **Sandbox is OS-level** : Codex uses Seatbelt on macOS, bubblewrap + seccomp on Linux, and MXC or the legacy`elevated` and`unelevated` sandboxes on Windows, not containers. The operating system enforces the restrictions on each command Codex spawns.
- **Hooks share Claude Code’s event names** : Codex registers fourteen hook events since v0.164.0. Twelve are`PreToolUse` ,`PermissionRequest` ,`PostToolUse` ,`PreCompact` ,`PostCompact` ,`SessionStart` ,`SessionEnd` ,`UserPromptSubmit` ,`SubagentStart` ,`SubagentStop` ,`Stop` , and`Interrupt` (eleven at v0.149.1, before`Interrupt` was added); the other two,`PreModelRequest` and`PostModelRequest` , only observe model requests and cannot block them. All are configured in`hooks.json` or inline`[[hooks.<Event>]]` tables, so most Claude Code hook configs port by moving the JSON and trusting it. Differences: every non-managed hook must be reviewed and trusted through`/hooks` before it runs,`prompt` and`agent` handlers are parsed but skipped, and Claude Code events outside these twelve (for example`Notification` ) have no counterpart; cover those with AGENTS.md instructions or skills.<sup>133</sup><sup>208</sup>
- **Sub-agents v2 (v0.117.0)** : Sub-agents now use path-based addresses (e.g.,`/root/agent_a` ) with structured inter-agent messaging and agent listing.<sup>75</sup> This extends the existing machinery (max 6 concurrent, reduced from 12 in v0.91.0). Multi-agent roles remain customizable via config (v0.104.0+).<sup>55</sup> The CSV fanout tool that v0.105.0 added (`spawn_agents_on_csv` ) was removed in v0.145.0 (#34413);`features.enable_fanout` still parses and does nothing.<sup>61</sup><sup>241</sup> Subagent workflows are on by default. Codex delegates when you ask it to, or when applicable`AGENTS.md` or skill instructions request it; switch between this session’s agent threads with`/subagents` , and open the command center for every active agent session with`/agents` .<sup>230</sup>
- **AGENTS.md is cross-tool** : Your AGENTS.md works in Cursor, Copilot, Amp, Jules, Gemini CLI, and 60,000+ open source projects. CLAUDE.md is Claude-only.
- **Profiles replace manual switching** : put each profile in its own file,`~/.codex/<name>.config.toml` , and select it with`--profile <name>` . Since v0.134.0 profiles are no longer`[profiles.*]` tables in`config.toml` .
