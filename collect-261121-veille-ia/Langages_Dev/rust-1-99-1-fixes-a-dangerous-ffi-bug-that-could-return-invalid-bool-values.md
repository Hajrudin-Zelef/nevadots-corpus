# Rust 1.99.1 Fixes a Dangerous FFI Bug That Could Return Invalid `bool` Values

## *The latest Rust point release fixes three regressions, including an x86_64 compiler miscompilation that could return unexpected bits across C interfaces. Here’s why the FFI issue deserves particular attention.*

A function returns `false`. The caller expects `0`. But the actual value arriving in the return register is `16`.

That sounds like a small implementation detail. It is not.

In Rust 1.99.0, a compiler regression caused some Rust functions returning `bool` through an FFI boundary to leave bits in the return register unspecified. On x86_64, a C caller could observe a value other than the expected `0` or `1`.

The problem was not in the application logic. It was in the machine code generated by the compiler.

On October 15, 2026, the Rust team released Rust 1.99.1 to fix this issue alongside two other regressions: a missing `wcslen` symbol affecting certain targets and a macOS linker problem involving `libLLVM`.

For developers who expose Rust libraries to C or other languages, the FFI fix is the most important part of this release.
