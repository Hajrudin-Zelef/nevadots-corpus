## Windows Secure Boot certificate expiration

Secure Boot certificate updates remain in progress as Microsoft transitions devices from certificates that began expiring in 2026 to newer certificates. Devices that have not yet received the newer certificates can continue to start and receive standard Windows updates. Microsoft will continue delivering the newer Secure Boot certificates to eligible devices through Windows Update.

## Improvements

This update includes improvements from the following previously released updates:

- October 13, 2026—KB5127648 (OS Builds 26300.9711, 26200.9711 and 26100.9711)
- October 26, 2026—KB5134133 (OS Builds 26300.9725, 26200.9725 and 26100.9725) Out-of-band
- October 28, 2026 — KB5127936 (OS Builds 26300.9818 and 26200.9818) Preview

**Applies to**: Windows 11, versions 26H2 and 25H2, all editions

This security update includes quality improvements. Key changes include:

- **[Security updates]** This update provides security improvements. For more information about the security vulnerabilities resolved by this update, see the Security Update Guide.
- **[Secure Boot]** This update includes additional high confidence device targeting data, increasing coverage of devices eligible to automatically receive new Secure Boot certificates. Certificate deployment via Windows updates continues across supported PCs and non-managed business devices in the coming months.
- **[Audio (known issue)]** - Fixed: USB Audio 1.0 devices might fail to start and display error code 10 in Device Manager after installing a recent security update.
- **[Printing]** Fixed: Adding a printer published in Active Directory through**Settings** >**Bluetooth & devices** >**Printers & scanners** >**Add device** might fail with error 87, “The parameter is incorrect.” This issue was introduced by the October 2026 update and does not generally affect existing printers or printing.
- **[Security]** This update improves NTLM security by enabling clients to offer NTLM message signing by default for non-anonymous connections. This change helps reduce exposure to NTLM relay attacks and provides auditing to identify connections that are not using signing. To learn more, see NTLM signing security improvements in Windows.
- **[Date and Time]** This update adjusts daylight saving time (DST) rules for Cuba for the extended 2026-2027 DST period. Cuba remains on UTC-04:00 and doesn't observe the November 2026 and March 2027 transitions. It returns to UTC-05:00 in November 2027 and resumes its regular seasonal schedule in 2028.
  - For the latest DST and time zone guidance, see the Daylight Saving Time & Time Zone Blog.
- **[Remote Desktop]** This update addresses an issue where Remote Desktop Protocol (RDP) connections might fail on the client due to a certificate mismatch after the October 2026 non-security preview update.
- **[Windows PowerShell]** This update strengthens security for PowerShell script signing and signature verification by introducing stricter encoding validation. As a result, scripts containing invalid UTF-8 encoding might fail signature validation, even if they were previously accepted. To resolve this issue, review the affected scripts, save them using valid UTF-8 encoding with a byte order mark (BOM), and sign them again. For further guidance, see Encoding Guidance for Signed PowerShell Scripts.

## Known issues in this update

## SQL Server linked server connections might remain open

**Symptoms**

After Windows updates released October 13, 2026, and later are installed on server devices, connections created by SQL Server linked server queries might remain open after the queries complete. As additional queries are performed, connections to external databases can accumulate instead of closing as expected. This can slow or degrade server performance after prolonged run time.

This issue affects SQL Server linked server queries that use OLE DB providers to connect to external databases. Oracle and PostgreSQL connections are among those known to be affected. In affected environments, administrators might observe an increasing number of open connections to external databases, even when the associated SQL Server linked server queries are no longer running.

If idle connections can be identified, it is possible to manually close them in order to temporarily relieve server load. It is also possible to temporarily restore system stability by restarting the SQL service. However, these steps can also interrupt active queries or transactions, and the problem can resurface again after sufficient operation time.

**Workaround:**

A mitigation is available for affected enterprise devices. To apply this mitigation in your organization, contact Microsoft Support for business.

**Next steps:**

We are working on a resolution and will provide an update in an upcoming release. We will update this documentation when the resolution is available

## November security update might fail to install on some devices

**Symptoms**

When attempting to install the November 2026 Windows security update KB5127936, some devices might be unable to complete the installation. Affected devices might repeatedly attempt to install the update or display error code 0x80070306, 0x800f0989, or 0x800f0993.

**Resolution**

The resolution for this issue automatically ran on affected devices connected to the internet and using Windows Update in Settings to install updates. No manual action from end-users was required to receive the repair. All affected devices should have been repaired within 24 to 48 hours of hitting the error, starting from November 11, 2026, 10am PT. Once your device received the repair, it automatically downloads and installs the November 2026 security update via Windows Update. You can also install the update by following these instructions.

If you still face installation issues, please use Windows help and learning or contact Microsoft Support.

### Deployment

If you deploy dynamic updates such as this update to an existing Windows image, ensure the **boot.stl** file is included as part of the installation media. Failure to include the file might prevent devices from successfully starting from the installation media and can result in error code `0xc0430001`.

Note

The **boot.stl** file is used during Secure Boot validation and must match the Windows version and architecture of the image you are updating.

To ensure the **boot.stl** file is included as part of the installation media, do one of the following:

- Use the Update WinPE script to update an existing Windows image. **(Recommended)**
- Manually copy the **boot.stl** file from the device**Windows\Boot\EFI** folder to the corresponding folder on your installation media before deploying the update.

For information about how to apply Dynamic Update packages to existing Windows images, see Update Windows installation media with Dynamic Update.
